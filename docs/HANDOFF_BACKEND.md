## Готово

- Flask API `/api/health`, `/api/evaluate` и маршрут шаблона `/`.
- Строгая проверка seed/JSON/Content-Type, ограничение тела 16 КиБ.
- Одна оценка на экземпляр приложения, немедленный 409 при занятой оценке,
  освобождение блокировки после ошибки, JSON 500 без traceback в браузере.
- Публичные функции `webapp.service.evaluate(seed)` и
  `webapp.app.create_app(*, evaluator=None)`. Инъекция evaluator предназначена
  для тестов; в обычном запуске выполняется настоящий Agent.
- Адаптер использует существующий `local_eval.evaluate_agent`, а не новую
  формулу оценки. Отдельный процесс с cwd корня проекта решает проблему
  относительных путей данных и изолирует состояние/вывод от HTTP-потоков.
  Запуск без shell текущим Python, timeout 600 секунд с остановкой процесса.
- Ошибки агента, перехваченные CLI-оценщиком, не превращаются в успех API.
  Неверные финальные тарифы/каналы/планы отклоняются существующим валидатором.
- Итоговые расходы и контакты включают пилоты и финальные кампании. В JSON
  только финальные кампании, без клиентских ID и скрытых параметров среды.
- Ошибки пилотов, fallback, пустая аудитория и обрезание скорингом видны в
  `warnings`; отсутствуют NaN/Infinity.
- Обновлено распределение равноправных ролей в `AGENTS.md`, сохранены правила
  безопасности; общий технический договор — `docs/WEB_CONTRACT.md`.

## Проверенное окружение и зависимости

Windows, Python 3.14.3; отдельное окружение `.tmpdeps/web-backend-venv`
(уже исключено существующим `.gitignore`). Глобальные пакеты не менялись.

Установлены Flask **3.1.3**, Werkzeug **3.1.8**, NumPy **2.5.3**, pandas **3.0.6**.
Существующий `requirements.txt` допускает проверенные NumPy/pandas.
`requirements-web.txt` и `.venv-web` оставлены направлению Султанали.

Временный способ повторить backend-проверку из корня проекта:

```powershell
python -m venv .tmpdeps/web-backend-venv
.\.tmpdeps\web-backend-venv\Scripts\python.exe -m pip install -r requirements.txt "Flask==3.1.3"
.\.tmpdeps\web-backend-venv\Scripts\python.exe -m unittest discover -s tests -p test_web_service.py -v
.\.tmpdeps\web-backend-venv\Scripts\python.exe -X utf8 local_eval.py
.\.tmpdeps\web-backend-venv\Scripts\python.exe -m webapp.app
```

Если окружение уже существует, не пересоздавайте его без необходимости.
После подключения скрипта Султанали основным способом станет `start_web.ps1`.
UTF-8 в команде CLI нужен для корректного русского вывода в Windows; на
вычисления не влияет. Worker API сам задаёт UTF-8 для вывода.

## Передать Асану

- Шаблон: `webapp/templates/index.html`; assets: `webapp/static/`.
- API и точные ключи — в `docs/WEB_CONTRACT.md`. В `filters` ключи **без**
  `filter_`. Канал рекламы называется `digital_ads`, не `ads`.
- 200 означает выполненную оценку, не обещание положительной прибыли.
  Показать warnings, отрицательные значения и пометку mock-среды.
- До наличия реального шаблона `/` возвращает 503 `FRONTEND_NOT_READY`.
  Backend не добавляет конкурирующую страницу или фиктивные данные.

## Передать Султанали

- `from webapp.app import create_app`; для искусственных ошибок:
  `create_app(evaluator=callable)`, callable принимает seed и возвращает dict.
  Для реальной интеграции: `create_app()`.
- При импорте сервер и оценка не запускаются. Импорт не создаёт `.env` и не
  читает секреты; `load_dotenv=False` при запуске сервера.
- Тестируемый child использует `sys.executable`, поэтому зависимости должны
  быть установлены в то же окружение, из которого запускается сервер.
- Таймаут HTTP-клиента для настоящей оценки учитывает предельные 600 секунд
  работы worker; обычный seed 42 в этой проверке занял около 1.7 секунды.
- Backend-тесты находятся в `tests/test_web_service.py`; твой независимый
  набор — `tests/test_web_api.py`. Backend-тест шаблона использует явно
  тестовый Jinja loader и **не считается визуальной проверкой сайта**.
