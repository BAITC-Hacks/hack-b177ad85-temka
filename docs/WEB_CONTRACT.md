Все участники равноправно пишут код, исправляют ошибки и коммитят. Наурызбай

Проверенная база агента: `4c3d89b`. Ветки: `codex/web-backend`,
`codex/web-frontend`, `codex/web-quality`. Интеграция — отдельная ветка
`codex/web-integration`, затем общая проверка, затем согласованный merge в main.
Нельзя одновременно переключать ветки в общей рабочей папке нескольких агентов:
каждый использует свой checkout/worktree. Коммиты участников сохраняют авторство.

## Назначение и границы

Локальная демонстрация настоящего агента на mock-среде. Это не официальный
submission и не прогноз результата скрытой проверки. Flask + HTML/CSS/обычный
JavaScript, без Node.js, CDN, runtime-LLM, облачных сервисов и клиентских ID в UI.
Оценка не использует интернет; первичная установка пакетов может его требовать.

Запуск из корня проекта: `python -m webapp.app`, адрес
`http://127.0.0.1:8000`. Python должен быть из окружения с Flask и зависимостями
`requirements.txt`. Скрипт `start_web.ps1`, `requirements-web.txt` и инструкция
установки — направление Султанали. Сервер локальный, debug/reloader выключены;
публичное размещение этой конфигурации не входит в задачу.

Веб-работа не меняет `agent.py`, код среды и скоринга, исходные CSV,
`local_eval.py`, `make_submission.py` и `submission.csv`. Стратегия и подготовка
официальной сдачи — отдельные задачи. Никто не делает force-push и не удаляет
чужие изменения. Перед коммитом каждый обновляет handoff своего направления;
`PROJECT_STATE.md` обновляется централизованно при интеграции.

## Интерфейсы Python

- `webapp.service.evaluate(seed: int) -> dict` — новая реальная оценка.
- `webapp.app.create_app(*, evaluator=None) -> Flask` — фабрика приложения.
  В тестах разрешено передать `evaluator(seed)` для симуляции ошибок/ожидания.
  При обычном запуске используется только настоящая оценка.
- `app.config.update(TESTING=True)` и `app.test_client()` — интерфейс API-тестов.
- Каждый вызов получает нового агента и новую среду. Между seed нет общего
  состояния; показатели и кампании повторяемы, время выполнения — нет.

Сервис вызывает публичный `local_eval.evaluate_agent` внутри отдельного процесса
с cwd корня проекта, используя текущий `sys.executable`, без shell. Это сохраняет
существующий скоринг и относительные пути данных, не меняя cwd HTTP-потоков.
Лимит процесса — 600 секунд; при превышении дочерний процесс останавливается.
Перехваченные CLI-оценщиком ошибки агента повторно поднимаются адаптером.
Скрытые параметры среды не читаются и агенту не передаются.

## HTTP

`GET /` отдаёт `webapp/templates/index.html`; статические файлы находятся в
`webapp/static/`. До интеграции шаблона возвращается **503** с кодом
`FRONTEND_NOT_READY`. Это временное состояние сборки, не готовый интерфейс.

`GET /api/health` возвращает **200** и `{"status":"ok"}`. Это liveness сервера,
не проверка наличия данных, frontend или успешности оценки.

`POST /api/evaluate` принимает `Content-Type: application/json` и ровно одно
поле: `{"seed":42}`. Seed — целое число 0..2147483647; boolean, float, строка,
null, пропущенное поле, лишние поля и повреждённый JSON запрещены. Максимальный
размер тела — 16 КиБ. Неверные запросы возвращают 400 без запуска агента.

Ответ 200 имеет поля:

| Поле | Тип / смысл |
| --- | --- |
| `seed` | целое число, seed запроса |
| `environment` | строка `mock` |
| `metrics.net_gain` | конечное число, чистый прирост после затрат |
| `metrics.total_cost` | конечное неотрицательное число, расходы пилотов **и** финальных кампаний |
| `metrics.total_contacts` | целое неотрицательное число, все контакты, не уникальные клиенты |
| `metrics.pilot_count` | целое число, фактически проведённые пилоты |
| `metrics.final_campaign_count` | число кампаний в `campaigns` |
| `campaigns` | массив только финальных кампаний |
| `warnings` | массив строк, в нормальном прогоне пустой |
| `duration_seconds` | конечное неотрицательное число, время всей оценки с запуском процесса |

Каждая кампания содержит `target_tariff` и `channel` (строки), `n_customers`
(фактическое число контактов после применения лимитов) и объект `filters`.
Ключи фильтров **без префикса `filter_`**: `current_tariff`, `arpu_segment`,
`data_segment`, `call_segment`. Неиспользуемые фильтры отсутствуют.
Значения — строки; список текущих тарифов может быть разделён `;`.
Имена каналов: `push`, `sms`, `digital_ads`, `call`.

Показатели считаются, не подставляются из известных результатов. В JSON нет
NaN/Infinity. Ошибки пилотов, fallback, пустая аудитория или обрезание скорингом
явно отмечаются в `warnings`. Неверный тариф/канал/план не превращается в
тихий успех с отброшенными кампаниями: запрос завершается ошибкой.

Формат ошибок: `{"error":{"code":"...","message":"Понятное сообщение"}}`.

| HTTP | code | Причина |
| --- | --- | --- |
| 400 | `INVALID_INPUT` | неверный запрос, Content-Type или слишком большое тело |
| 409 | `EVALUATION_BUSY` | одна оценка уже выполняется в этом экземпляре приложения |
| 500 | `EVALUATION_FAILED` | ошибка агента/скоринга/сериализации, отсутствующие данные или таймаут |
| 503 | `FRONTEND_NOT_READY` | только для `/`, пока не добавлен шаблон |

Сообщения ошибок на русском, без traceback и путей. Подробности — в терминале
сервера. Ошибка или нечисловой результат не удерживают блокировку. Блокировка
действует в одном экземпляре приложения; многопроцессное развёртывание вне задачи.
Обычный запуск использует threaded-сервер, позволяющий сразу вернуть 409.

## Критерии общей готовности

1. Установка в новом окружении и воспроизводимый локальный запуск.
2. Реальный запрос seed 42; метрики совпадают с CLI-оценкой в том же окружении.
3. Работают неверный ввод, отказ сервера, 409, 500 и повтор после ошибки.
4. Нет подмены результатов или утечки клиентских ID.
5. Лимиты: 20 пилотов, 15000 контактов, 100000 бюджета, 1–10 финальных кампаний,
   максимум 5000 клиентов на кампанию; пилоты и финальные кампании различаются.
6. UI проверен на реальном API; моки не считаются end-to-end проверкой.
7. Есть инструкции, handoff, SHA и сохранённые авторские коммиты всех участников.
