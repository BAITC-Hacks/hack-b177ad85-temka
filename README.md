# Beeline Tariff Marketing Campaigns

Агент выбирает тарифные кампании через разведочные и повторные пилоты.
Локальное веб-приложение запускает этого же агента на mock-среде, показывает
чистый результат, расходы, контакты, пилоты и финальные кампании.

Веб-обёртка использует Flask, HTML/CSS и обычный JavaScript. Node.js, облачные
сервисы, ключи API и runtime-LLM не нужны. Оценка работает без интернета;
первичная установка зависимостей может потребовать доступ к PyPI.

## Установка и запуск в Windows

Нужны Git, Python с модулем venv и PowerShell. Проверенная конфигурация
интеграции: Windows 11, Python 3.14.3, Windows PowerShell 5.1, Flask 3.1.3.
Другие конфигурации требуют отдельной проверки.

В PowerShell, из корня полученной интеграционной ветки:

```powershell
.\start_web.ps1
```

Скрипт создаёт отдельную `.venv-web`, устанавливает `requirements-web.txt`
и запускает сервер её Python. Его можно вызвать и из другой папки, указав
полный путь к скрипту. После изменения зависимостей используйте
`.\start_web.ps1 -Reinstall`.

Откройте [локальное приложение](http://127.0.0.1:8000).
Для остановки нажмите Ctrl+C в терминале сервера. Не переключайте ветку
в папке работающего сервера; сначала остановите свой сервер или используйте
отдельный worktree. Занятый порт не освобождается автоматически.

Если PowerShell запрещает запуск скриптов, можно вообще не использовать ps1:

```powershell
python -m venv .venv-web
.\.venv-web\Scripts\python.exe -m pip install -r requirements-web.txt
.\.venv-web\Scripts\python.exe -m webapp.app
```

Выполняйте команды по очереди и останавливайтесь при ошибке. Активация
окружения, права администратора и изменение системной ExecutionPolicy
не нужны. Дополнительные варианты и диагностика: `docs/LOCAL_WEB.md`.

## Как пользоваться

1. Введите целый seed от 0 до 2147483647, например 42.
2. Запустите оценку и дождитесь результата.
3. Посмотрите метрики и таблицу финальных кампаний.

В одном экземпляре сервера одновременно выполняется одна оценка.
Второй запрос получает 409. Результаты вычисляются заново, а не берутся
из демонстрационных чисел. Ошибки не должны блокировать следующий запуск;
подробности ошибки смотрите в терминале.

## Проверки

Из корня проекта используйте тот же Python, что и сервер:

```powershell
.\.venv-web\Scripts\python.exe -m pip check
.\.venv-web\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv-web\Scripts\python.exe -X utf8 local_eval.py
.\.venv-web\Scripts\python.exe -X utf8 local_eval.py --runs 10
```

Перед оценкой прочитайте `.codex/skills/hackathon-eval/SKILL.md`.
Одиночная оценка и серия из 10 seed — разные проверки; выполненные команды
и окружение фиксируются в handoff, а не предполагаются по наличию теста.

При штатном тестировании намеренно моделируются ошибки: traceback в тесте
восстановления допустим, если итог unittest — OK. Тестовый клиент Flask
и HTTP-проверки не заменяют проверку интерфейса в настоящем браузере.

## Ограничения и официальная сдача

- До 20 пилотов, всего до 15 000 контактов и 100 000 бюджета.
- От 1 до 10 финальных кампаний, до 5 000 клиентов на финальную кампанию.
- Пилоты тоже расходуют бюджет и контакты. CLI может показывать общее число
  пилотов и финальных кампаний: это не лимит в 10 финальных кампаний.
- Mock-среда содержит синтетические эффекты. Положительный локальный результат
  не гарантирует результат на скрытой проверке.
- Сервер доступен на loopback, debug и reloader отключены. Это локальное
  демонстрационное приложение, не конфигурация публичного production-сервера.
- Сайт не генерирует и не обновляет `submission.csv`. Официальная сдача
  выполняется отдельно по `PARTICIPANT_GUIDE.md`. Генерация через
  `make_submission.py` требует отдельного решения команды; веб-проверка
  не подтверждает готовность существующего submission.

## Команда и GitHub

Все участники равноправно реализуют, тестируют и коммитят свои изменения.

| Участник | Зона координации |
| --- | --- |
| Наурызбай | Backend, подключение агента, общая интеграция. |
| Асан | Интерфейс и браузерная проверка с настоящим API. |
| Султанали | Установка, запуск, автоматические тесты и независимая QA-проверка. |

Общий договор — `docs/WEB_CONTRACT.md`. Ветки компонентов:
`codex/web-backend`, `codex/web-frontend`, `codex/web-quality`.
Общая сборка — `codex/web-integration`. История и авторство сохраняются
обычными merge, без squash. Наурызбай согласует последующее объединение
в main после независимой проверки; сама интеграция ещё не релиз.

Перед работой прочитайте `AGENTS.md`, `PROJECT_STATE.md`, свой handoff,
выполните `git status` и `git log -3 --oneline`. При незнакомых изменениях
не удаляйте их и не переключайте ветку вслепую. Для параллельной работы
используйте отдельные checkout/worktree. Не применяйте force-push.

Одна законченная задача — один содержательный коммит. Добавляйте явно
нужные файлы; не коммитьте окружения, секреты, кэш или логи. Каждый обновляет
handoff своего направления. Центральный `PROJECT_STATE.md` обновляет
интегратор, чтобы участники не правили его одновременно.
`submission.csv` не игнорируется, но веб-задачи его не меняют.

Текущее состояние и следующие задачи — в `PROJECT_STATE.md`.
Воспроизводимые результаты общей сборки — в `docs/HANDOFF_INTEGRATION.md`.
Отчёты компонентов и прежние `TASK_*.txt` описывают свои этапы и не
заменяют текущий договор или итоговую интеграционную проверку.
