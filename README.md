# Beeline Tariff Marketing Campaigns

Агент для выбора тарифных маркетинговых кампаний с адаптивными пилотами.

## Быстрый запуск

```powershell
python -m pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

Точка входа для проверки — `agent.py`, класс `Agent`, метод `act(env)`.

## Текущий baseline

В `agent.py` пока находится исходный шаблон организаторов. На 10 локальных
seed'ах он получил отрицательный результат во всех 10 прогонах:

- медиана: `-357 948`;
- минимум: `-1 019 431`;
- максимум: `-76 493`.

Это технический baseline, а не готовая стратегия.

## GitHub-процесс

Удалённый репозиторий уже настроен как `origin`. Перед каждой задачей работайте из корня проекта:

```powershell
git switch main
git pull --ff-only origin main
git switch -c codex/<короткая-задача>
```

Основные ветки: `codex/agent-pilots` для Наурызбая, `codex/candidate-research` для Асана и `codex/eval-report` для Султанали. Только Наурызбай сливает готовые изменения в `main`.

Перед коммитом обновите `PROJECT_STATE.md`, затем добавляйте только файлы своей задачи:

```powershell
git add <нужные-файлы> PROJECT_STATE.md
git commit -m "feat(agent): краткое описание"
git push -u origin codex/<короткая-задача>
```

Не используйте `git push --force`. Не редактируйте один файл параллельно, особенно `agent.py`. Не коммитьте `.env`, API-ключи, `.venv`, `__pycache__` и логи. `submission.csv` не игнорируется: он обязателен для сдачи.

## Контекст для Codex

В начале каждого нового запроса к Codex используйте шаблон:

```text
Прочитай AGENTS.md, PROJECT_STATE.md и git log -3 --oneline.
Моя роль: <Наурызбай / Асан / Султанали>.
Задача: <один конкретный результат>.
Разрешено менять: <файлы>.
Не менять: <файлы>.
Проверка: <точная команда>.
После работы обнови PROJECT_STATE.md до коммита и кратко перечисли изменения.
```

`PROJECT_STATE.md` - единственный источник текущего статуса; он обновляется до каждого коммита вместе с кодом. `README.md` содержит постоянные правила и не переписывается ради обычного прогресса.

## Skills и subagents

Для запуска или разбора `local_eval.py`, а также подготовки `submission.csv`, используй skill `.codex/skills/hackathon-eval`. Если `$hackathon-eval` доступен в списке skills текущей сессии, вызови его; иначе сначала попроси Codex прочитать `.codex/skills/hackathon-eval/SKILL.md`.

Subagents используйте только для независимой работы: анализ исторических переходов, ревью логики или разбор отчётов тестов. В запросе агенту указывайте конкретный ожидаемый результат и разрешённые файлы. Несколько агентов не должны одновременно менять `agent.py`; итог интегрирует Наурызбай.

## Ограничения

- до 10 финальных кампаний;
- до 5000 клиентов в кампании;
- до 15 000 контактов вместе с пилотами;
- бюджет до 100 000 у.е. вместе с пилотами;
- до 20 пилотов по 10–200 клиентов.
